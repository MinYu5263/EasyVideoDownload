# Cookie 文件

Cookie 与 `app.db` 使用同一应用数据目录，在其下单独建立 `cookies` 文件夹。Windows 路径为
`%LOCALAPPDATA%\EasyVideoDownload\cookies`，其他系统沿用 `local_data_dir()/EasyVideoDownload/cookies`。

| 平台显示名称            | 标识       | 文件名                 |
|-------------------------|------------|------------------------|
| 抖音（英文界面 Douyin） | `douyin`   | `douyin_cookies.txt`   |
| Bilibili                | `bilibili` | `bilibili_cookies.txt` |
| YouTube                 | `youtube`  | `youtube_cookies.txt`  |

- 打开平台的 Cookie 配置时，桌面端通过 `get_cookie_contents` 读取现有文件。文件不存在返回空文本，不创建空文件。
- 导入文件、剪贴板粘贴及直接编辑共用文本框，内容变化通过 `save_cookie_contents` 自动写入。首次写入自动创建目录与文件。
- 保存按平台串行执行，保留最新编辑内容，不会让较早的请求覆盖较新的文本。
- 清空内容时移除当前平台文件，重复清空不会报错，其他平台文件保持原样。
- 不校验 Cookie 格式或平台域名。读取失败时禁止覆盖未读取的文件；读写失败使用短暂消息提示，文本框下方不增加信息。
- 保存失败保留文本草稿；再次导入、粘贴或清空会重试。重新打开配置也会重试当前草稿，避免旧文件覆盖未保存的修改。
- Rust 使用同目录临时文件写完后替换正式文件，写入失败不留下截断文件。临时文件由 `tempfile` 管理和清理。
- 剪贴板读取与命令复制使用 Tauri 原生剪贴板插件，分别授予文本读取和文本写入权限；文件导入由 Rust 打开系统文件选择器并读取
  UTF-8 文本，取消选择不改变现有内容。没有浏览器 API 回退。
- 普通浏览器页面不支持系统操作或视频解析，真实文件读写仅在 Tauri 桌面端执行。

视频解析已通过 Rust 调用设置中检测成功的 yt-dlp；解析前等待当前平台的 Cookie 保存队列完成，保存失败时阻止解析。
yt-dlp 会回写 Cookie jar，因此使用当前平台文件内容的临时副本并将其绝对路径传入 `--cookies`，避免覆盖文本框维护的文件。
副本在解析结束或失败时自动删除；没有 Cookie 内容时省略该参数。仍不在编辑时检查 Cookie 格式，yt-dlp 的实际解析失败通过应用内通知提示。
下载通过 Rust 原生执行器调用 yt-dlp/FFmpeg。下载页提交前等待页面状态、平台代理与 Cookie 保存成功；历史和任务卡片中的重新下载也等待对应平台的设置与
Cookie 保存，失败则阻止提交。Cookie 临时副本保留到下载进程结束，不覆盖维护中的正式文件。历史记录从原生接收入队开始保存；同一视频的重试复用记录，准备失败与取消也会结算。
目前只支持单视频，视频合集及 yt-dlp 的 `multi_video` 分段结果明确报告暂不支持，避免将第一段显示为完整视频。
首次使用的默认平台取工具栏第一项，后续恢复已保存的工具栏选择。

YouTube 配置了 Cookie、且 yt-dlp 返回 `The page needs to be reloaded` 的特定播放器错误时，原生解析会再尝试一次不带 Cookie
的公开访问。
成功结果标记 `cookieFallback`，页面说明本次使用公开访问；原文件不清空、不修改。其他平台、网络错误及没有 Cookie 的请求不会触发这次重试。
两次尝试共用 90 秒超时；公开访问也失败时如实显示失败，不把需登录的视频显示为解析成功。

三平台各自通过 SQLite 保留最新解析结果、格式顺序、精确格式选择、画质、帧率和保存目录，切换平台及重启不重新解析。
打开、关闭、修改或清空 Cookie 配置均保留该平台已有结果和选项；下一次手动解析等待保存完成并使用最新 Cookie。
页面仅保存当前输入链接。修改、粘贴不同链接或清空输入时清除该平台可执行的旧结果、格式和画质/帧率选择，保留保存目录；界面暂时保留最近成功的封面与标题，但必须重新解析成功后才能下载。输入未变化时保留已有结果，手动刷新同一链接失败也保留其对应结果并显示错误。
已应用的 yt-dlp/Deno 路径、版本或来源改变会清除全部结果；重启时由工具指纹检查旧结果。手动点击解析总是重新调用原生解析，保留的结果用于展示和对应链接的命令、下载。页面状态保存到
SQLite，封面缓存由 Rust 保存到应用数据目录的 thumbnails 文件夹。

解析结果卡片和下载卡片的右上角各有一个终端图标，悬停显示用途，点击打开可复用的 `CommandViewer` 应用内弹窗。
解析结果卡片在等待、解析中、失败和成功时均显示同一个外框，标题固定为“解析结果”。失败时使用 Element Plus
`ElNotification.error`
在应用右上角直接显示原因和原生错误详情，内容按纯文本渲染，长错误允许滚动。通知不自动消失，可手动关闭；下一次解析或组件卸载时关闭本组件的上一条通知，避免堆叠。切换到缓存的失败状态不重新弹通知，已取消的解析不通知。不在卡片内展示错误或切换标题状态。
解析或下载遇到工具未配置、工具配置读取失败或 yt-dlp 无法启动时，通知显示“去配置”按钮，点击后关闭通知并打开“设置 → 必备工具”。
没有成功结果时，封面使用 Element Plus 的 `rect` 骨架，右侧上方标题组合 `h1` 和 `text` 为两行，下方用两段短 `text`
骨架对应格式和大小；右侧区域与真实结果共用上下布局。首次等待时为静态，真实解析期间启用动画。
封面标题层和画质帧率层始终保留统一的父容器，通过 20px 的 `gap` 设置间距，不再依赖 Skeleton 插槽内容的外边距。
同一输入已有结果时，再次解析期间继续展示，不重新出现骨架屏；结果内容仅降低透明度并设为 `inert`
，画质和帧率临时禁用，不展示遮罩、动画或遮罩文字。结束或失败后恢复。输入变化后旧结果已清除，新链接解析期间显示骨架屏。
画质和帧率始终显示为下拉框：尚无元数据时选项为空，单个真实选项也允许展开，仅解析期间临时禁用。不提供格式下拉框。
解析成功后，在视频封面右侧、标题下方展示所选视频流的格式与大小，选择变化时同步更新。大小优先使用 yt-dlp 的 `filesize`，其次使用
`filesize_approx`，直接展示换算后的数值与单位，缺失或无效时为“未知”。大小使用 SI 词头的十进制字节单位（kB/MB/GB，每级 1000
倍），下载速率使用相同换算并附加
`/s`；该大小不包含独立音频，悬停提示说明含义。
弹窗使用 Element Plus 的 `ElDialog`，追加到 body 并居中显示；按需加载 Dialog（含 Overlay）和 Tooltip（含 Popper）的组件样式。
两个命令图标在没有对应结果时禁用；有结果时使用该结果成功解析的链接，与正在编辑的输入草稿无关。
Rust 通过 `get_video_parse_command` 共用实际解析的参数构造函数，按结果对应链接、已应用工具路径和 Cookie 配置生成命令。
查看不启动进程、不创建 Cookie 副本，也不修改文件。Windows 输出带调用运算符和参数转义的 PowerShell 命令，其他系统使用 Shell
单引号转义。
为了使复制的命令可再次运行，展示维护中的 Cookie 文件路径；应用实际执行使用解析结束即删除的临时副本。
不展示 Cookie 原文。命令表示当前配置下的首次解析请求，YouTube 的公开访问重试另由解析器按实际错误决定。
“复制命令”通过原生 `write_text` 写入剪贴板，失败保留命令供重试，不回退到浏览器 API。

`get_video_download_command` 按当前所选视频流的 `formatId`、绝对保存目录和已配置的 yt-dlp/Deno/FFmpeg
路径生成下载命令，仍只预览、不启动下载。
视频流按 ID 精确匹配：仅视频的流有独立音频时搭配音频，已有音频的视频或无音轨的视频使用原流；命令不添加格式转换、强制输出容器或重新封装参数。
预览不创建输出目录、不写 Cookie；未选择保存目录或缺少 FFmpeg 时显示原因。
应用内下载按钮已接入真实执行；进度来自原生下载输出，最终成功需要验证选定目录中存在非空视频文件。

三平台的分享文本统一在前端通过 `extractVideoLink` 提取第一个 HTTP (S) 链接，再检查协议、域名与平台。
视频解析和两种命令预览都调用同一验证方法；Rust 继续校验收到的 URL，不必再解析 Bilibili/YouTube 的分享文案。
解析元数据保留 yt-dlp 顶层及每个视频格式的 `ext`。画质和帧率只展示真实返回的数值，缺失时为空；没有“自动选择”或“最高可用”选项。
解析后默认选择最高画质及其最高帧率；切换画质时选择该画质下的最高帧率。相同画质和帧率的多个格式保留 yt-dlp 的偏好顺序，取最后一个。
所选视频流的 `formatId` 决定下载命令，不提供格式选择或容器转换；格式仅随所选流展示。标题上方不再重复显示平台名。
链接使用 Element Plus 的普通 `clearable` 输入框；原生粘贴按钮放在输入框右侧、解析按钮前，使用剪贴板粘贴图标。
粘贴调用原生剪贴板读取，立即通过共用 `extractVideoLink` 提取 HTTP (S) 链接，保留链接的完整查询参数；手动粘贴的分享文本仍在解析前通过相同方法处理。
没有链接的非空剪贴板内容保留为去除首尾空白的文本，读取失败报告错误，空剪贴板保留已有内容。
读取期间的新编辑、清空、平台切换、离开页面或打开 Cookie 配置会使旧剪贴板结果失效，避免覆盖当前输入。
