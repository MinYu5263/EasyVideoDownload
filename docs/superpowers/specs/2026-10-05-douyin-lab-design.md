# 抖音实验页设计

日期：2026-10-05。状态：用户已批准并实现；自动测试和原生后端验证完成，实验页目录选择及交互仍待桌面手动验收。

## 目的与范围

首版已发布。新增侧栏入口“抖音实验”，在独立页面验证 Rust HTTP 解析与直链下载，验证通过后再决定如何接入正式下载页面。

首版实验支持：单条抖音视频链接、读取已有 Cookie 和代理配置、查看并选择真实格式、直链下载、取消操作，以及下载后的实际媒体信息核对。解析使用自定义
Rust HTTP 实现。

不在本次接入正式下载队列、历史记录或数据库迁移。不引入浏览器自动化、自动获取登录 Cookie、批量下载和断点续传。实验失败时展示明确错误；现有主页面仍可使用原来的
yt-dlp 流程。

## 隔离方式

- `src/navigation.ts` 新增导航数据，`src/App.vue` 接入实验页面；侧栏沿用现有组件。
- 实验页首次访问时才挂载，访问后切换页面保留当前状态。未访问时不初始化实验网络操作或事件监听。
- 实验导航状态保存在本次应用会话内；已有 download/history/settings 的导航偏好继续按现有方式持久化，无需扩大数据库允许的页面枚举。
- 页面、前端状态、Rust 命令、后台任务状态和事件独立；不改现有解析器、格式筛选、下载命令和历史写入逻辑。
- Cookie、代理与工具配置仅通过现有原生接口读取。实验页不修改主页面输入、格式选择或已导入 Cookie。
- 默认输出到独立的 `Videos/EasyVideoDownload/douyin-lab` 目录；允许通过 Tauri 原生目录选择器更改目录。文件重名时生成新文件名，不覆盖已有文件。
- 工作区已有的 HistoryPage、导航和中英文文案修改必须保留。

## 页面流程

页面包含实验说明、链接输入、解析按钮、格式列表、下载目录、下载/取消按钮、真实进度与结果信息。未配置 Cookie 时提示用户到现有页面导入。

解析结果展示标题、封面及候选格式的分辨率、编码、帧率、码率、文件大小和水印状态。未知字段显示“未知”，不凭格式名称或估算值冒充实测数据。列表不展示
Cookie 或带签名的完整媒体 URL。

默认按真实分辨率选择较高画质，同分辨率优先 H.264 以便播放兼容；保留 H.265 供用户选择。未知帧率不直接淘汰。跨编码不单凭码率判断画质。已知带水印的候选需要明确标识。

实验页同一时刻允许一个解析或下载操作，不新增队列。切换侧栏不取消后台操作；新的解析操作在上一操作结束后才能启动。应用重启后清空实验状态。

## Rust 解析与格式数据

新增独立的抖音模块与实验命令，模块内部区分 HTTP 解析、格式整理、直链下载及任务管理，便于未来接入正式页面。

1. 接受抖音短链和视频详情链接，解析重定向得到视频 ID；拒绝其他平台及不支持的作品类型。
2. 读取导入 Cookie 的快照，按域名、路径、过期时间和 HTTPS 规则发送；读取本次操作的代理快照。Cookie 不进入前端、日志或可序列化事件。
3. 请求网页详情接口，携带 `aweme_id`、`aid=6383`、`channel=channel_pc_web`、`detail_list=1`，以及合适的 UA 和 Referer。
4. 收集 `bit_rate` 和视频地址字段。读取地址结构中的真实 width/height/data_size，读取实际码率和
   FPS；格式名称只作辅助说明，不作为真实分辨率的唯一依据。
5. 同一媒体编码的多个 CDN URL 作为镜像保存；不同编码、分辨率或码率不能因为分辨率相同而合并。生成稳定格式 ID。

前期对视频 `7688950275142389027` 的实测中，加入 `aid=6383` 可使返回格式从最高 720p 扩展到包含 1080p；这一结果作为回归样本，不承诺所有作品都提供
1080p。无 Cookie 的请求曾返回空内容，本版复用用户已导入的 Cookie。

Rust 保存解析结果及其 Cookie/代理快照；前端下载请求只提交解析结果 ID、格式 ID 和输出目录，媒体 URL
从原生缓存取得。新一轮解析替换旧的结果，失效结果不能继续下载。

## 下载与生命周期

下载使用真实选中格式的原始媒体，不转码。以本任务唯一命名的临时文件接收数据，成功校验后再落为正式文件；取消或失败只清理本任务的临时文件。

网络操作需有超时与取消机制；可依次尝试候选镜像。签名过期时允许刷新详情一次，只接受原格式的稳定
ID（由视频身份、编码、尺寸、帧率、码率、大小、水印状态和平台格式键组成）；无法确认同一格式时要求重新解析选择，不静默降级。

进度来自实际接收字节；总大小未知时显示已下载字节，不伪造百分比。完成状态在文件写入和媒体核对之后产生。使用现有工具配置中的
ffprobe 核对实际分辨率、编码、时长、码率和文件大小；工具缺失时允许解析，但禁用实验下载并说明原因。

后台任务具备任务 ID 与状态版本；前端忽略过期事件，并在重新连接时读取原生状态快照。实验事件使用独立名称，不进入正式下载事件处理器。

正常关闭窗口沿用现有托盘行为；真正退出应用时，现有退出协调流程必须同时取消并等待实验任务，包括网络传输、文件写入和 ffprobe
子进程。仅增加实验任务的退出协调，不重构主下载管理器。

## 验收条件

- 原有下载、历史、设置及已存在的工作区修改保持正常；未打开实验页时不发生实验请求。
- 实验页读取已导入 Cookie，解析短链并展示真实候选格式；缺少 Cookie、空响应和不支持链接均给出明确错误。
- 用既有样本核对 1080p H.264 与 720p H.265 候选，下载后 ffprobe 报告的实际尺寸与选中格式一致。平台响应变化应明确记录，不能使用假数据补齐候选。
- 下载取消、网络失败、镜像失败、重名、切换页面和退出应用均不污染正式队列、历史或已有文件。
- 运行相关 Rust 测试、前端类型检查和构建；通过桌面端真实调用验证 Cookie 读取、目录选择、下载与取消。浏览器预览只能用于界面检查。
- 不执行 Git 提交、推送、分支或 worktree 操作。
