# EasyVideoDownload 立项讨论稿

创建：2026-10-02；更新：2026-10-03。依据：项目 README 与本轮用户反馈。v0.6 原型界面与交互已按用户确认定稿；随后用户调整为跨平台、两种工具来源，并确认前端技术。最新约束以本文“技术选型与范围调整”为准；HTML 原型尚未同步移除应用下载，解析、连接与下载仍为模拟。本文不是正式开发实施计划。

## 想解决的问题

把现有 yt-dlp 的下载能力变成容易操作的跨平台桌面工具，目标为 Windows、macOS、Linux。核心价值是减少操作，让用户下载当前账号可以访问的最高可用画质，并明确找到最终文件。

已确定：Tauri 2 + Rust、Vue 3 + TypeScript + Vite + Element Plus、yt-dlp 为核心、复用已有工具，主要关注 Bilibili、抖音、YouTube。现有目录包含文档与模拟原型，尚未搭建正式应用。

本轮用户确认：一次下载一个视频，操作尽量少。原型据此采用单视频主流程；队列与合集暂缓。

## 三种方向

| 方向 | 适合的习惯 | 成本与取舍 |
| --- | --- | --- |
| 单视频下载，少量完成记录（建议先讨论） | 每次保存一个视频 | 最容易验证完整流程；首版不支持多任务并行 |
| 轻量任务队列 | 连续粘贴多个独立视频链接 | 需增加排队、逐项取消、重复任务与队列状态设计 |
| 合集与内容管理 | 大量下载播放列表、整理素材库 | 范围显著扩大；还需选集、批量失败处理、组织文件等能力 |

## 技术选型与范围调整

2026-10-03，用户确认以下调整：

- 目标平台为 Windows、macOS、Linux，构建打包使用 Tauri 的标准工具，平台构建与验证在开发、发布阶段处理。

- Cookie 按平台以 Netscape 文本文件保存到应用数据目录，通过 Tauri PathResolver 获取路径；日志不记录凭据内容。

## 首版范围与原型对应关系

1. 在工具栏手动选择 Bilibili、抖音或 YouTube，再输入单视频链接；支持从抖音分享文本中提取链接。平台选择决定配置，链接不匹配时提示用户，不自动切换平台。
2. 解析后展示封面、标题与时长，并选择画质、帧率与格式。封面缺失或加载失败时显示占位，时长缺失时隐藏标签；画质或帧率缺失时提供自动选择，不展示作者与预计大小。
3. 选择保存目录；记住上次目录。文件容器暂以已验证命令中的 MKV 为讨论起点。
4. 显示解析、下载视频、下载音频、合并、完成等状态。支持取消和失败后重新开始。
5. 成功后显示最终路径，提供打开文件、打开文件夹与查看下载记录入口；保留轻量完成记录，支持单条删除、清空和撤销。删除记录不删除本地视频。
6. 设置页从上到下排列系统设置、必备工具、关于三个模块，不提供模块切换栏。工具仅提供系统 PATH 与手动选择两种来源；显示最终使用路径与检测版本。v0.6 HTML 中的应用下载演示待移除。
7. Cookie 从当前平台工具栏右侧进入，统一在工具栏下方展开导入面板，暂时替换下载内容，关闭后恢复。设置页不放 Cookie 配置。提供文件导入与粘贴两种方式，支持连接检查与移除配置。网络可达、视频可解析与登录成功应区分。

完成记录用于找回文件；历史保存策略与容量留到正式实现时确定。

## 可点击原型

打开同目录的 `prototype.html` 即可，无外部资源或依赖。

- 默认进入未解析的首页：链接为空，显示等待提示，下载按钮禁用。点击“载入示例”体验解析结果；顶部“初始状态”可随时返回空白首页（任务执行时禁用）。
- 顶部平台工具栏明确选择平台，每个平台保留各自链接、目录和文件格式草稿；切换后需要重新解析。右侧 Cookie 导入按钮打开当前平台的导入界面，各平台配置互不共享。
- 侧栏入口与页面标题均为“视频下载”；侧栏品牌保留 EasyVideoDownload，移除原有英文和标题说明。卡片标题不再显示步骤数字。
- 所有卡片按内容自然排列，随整页一起滚动，没有独立滚动区和固定底部卡片。下载按钮始终保留在下载卡片内。
- 解析卡片显示成功状态、封面、标题、时长、画质、帧率和格式。封面位于标题左侧，时长显示在封面右下角；封面缺失或加载失败时显示占位，未返回时长时不显示时长标签。格式为 MKV/MP4 输出容器，下载卡片只保留保存目录。Bilibili/YouTube 示例中 2160p、1080p 有 60/30 fps，720p 仅有 30 fps；抖音示例仅提供 1080p/720p、30 fps。这些是交互示例，不能据此承诺平台画质。实际组合应来自解析结果。
- 进度条在下载卡片中单独占一行，铺满卡片内容宽度，位于保存目录下方、状态与按钮行上方。下载和完成时显示；该行预留空间，避免下载前后挤动按钮。
- 主按钮在同一位置切换为开始下载、取消下载、再次下载或重试下载。完成后提供“查看下载记录”，由用户主动跳转；也可直接再次下载或修改链接，不自动跳转。
- 示例封面、标题、时长、画质和下载进度全部是模拟。封面为原型内嵌示意图，不展示作者、预计大小和虚构速度；选择顶部“解析信息缺失”，再解析，可查看无封面、时长、标题、画质与帧率数据时的兜底状态。
- 可以修改链接并解析示例、选择画质、帧率与格式、编辑目录、体验模拟下载与合并。完成记录保留所选帧率和格式。
- 原型顶部选择下载成功、Cookie 失效、目录不可写或合并失败，体验下一步入口；同一失败场景下重试仍会失败，切到成功场景再重试可观察恢复。
- 可以取消、重新开始、查看记录、删除单条、清空和撤销最近一次记录操作。空列表禁用清空按钮。刷新页面即清除模拟记录及设置。
- 点击工具栏右侧打开当前平台的 Cookie 展开面板，暂时替换下方下载内容，关闭后恢复；已移除布局切换与弹窗版本。文件导入仅取文件名，粘贴仅检查格式与平台域名，不保留内容；关闭编辑器后清空草稿。支持示例文件与无凭据的示例文本。
- 检查通过显示“网络可达、示例可解析”，不显示账号已登录或会员身份。没有 Cookie 时也可模拟检查公开视频连接。
- 打开文件与文件夹只显示模拟提示，不产生真实下载。Cookie 修改或移除后清除当前解析结果；下载期间仍使用本次任务快照。
- Cookie 异常后需重新导入，并返回主页重新解析。正式应用不得沿用失效账号解析出的格式。

## v0.4 原型调整记录与可行性边界

根据本轮截图与反馈，增加手动平台工具栏、三张独立 Cookie 卡片与连接检查状态，精简解析结果，并补充记录删除、清空与撤销。

核对 [yt-dlp 官方 README](https://github.com/yt-dlp/yt-dlp#output-template)：解析元数据与格式属性依赖平台和提取器，并非所有视频都有。正式实现应使用结构化输出获取标题和可用格式；没有分辨率或帧率时提供自动选择。解析成功也不保证所有格式最终能下载，需以真实视频逐平台验收。

核对 [yt-dlp 官方 Cookie FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp)：支持通过 Cookie 文件导入，文件需采用 Mozilla/Netscape 格式。提供导入入口不表示每个平台在所有情况下都可下载，也不能由网络通畅推断登录有效。当前仅核对文档，未验证用户 Cookie 或执行平台下载。

## v0.5 原型调整与首版建议

以下保留当时的设计记录。其中三种工具来源、应用下载及其更新管理已被本轮“两种工具来源”决定替代。

Cookie 从设置移到平台工具栏；下载完成增加查看记录入口；设置拆成系统设置、必备工具、关于。保留现有配色、自然页面滚动和整行进度条。

### Cookie 布局比较

| 方案 | 交互 | 取舍 |
| --- | --- | --- |
| 弹窗（比较稿，定稿未采用） | 在当前下载页上方配置，关闭回到原处 | 适合偶尔配置，保留下载上下文；窄窗口中弹窗内容可滚动 |
| 展开面板 | 工具栏下方切换为导入面板，关闭恢复下载内容 | 粘贴区域更宽，但暂时看不到下载卡片 |

v0.5 曾提供两种布局供比较，v0.6 按用户选择仅保留展开面板。文件和粘贴均按 Netscape 格式设计，粘贴时检查文件头、数据行列数、平台域名；暂不支持把任意 Cookie 请求头或 JSON 直接转换为凭据。原型只对用户输入做格式演示，保存后清除粘贴内容，不写入浏览器存储、不上传、不建立真实平台连接。正式应用的本机凭据保存方式仍待实现设计。

系统设置目前设计简体中文、繁体中文、English 选择；此轮仅演示选项状态，没有完成整个应用的翻译。关于页面显示项目、版本、目标平台和核心工具链接。

### 三种工具来源都建议保留

| 来源 | 用途 | 交互 |
| --- | --- | --- |
| 系统 PATH（默认） | 复用已有安装 | 检测 PATH，展示找到的程序路径与版本 |
| 手动选择 | 已安装程序未配置环境变量 | 选择可执行文件；FFmpeg/FFprobe 选择所在目录，检测后使用 |
| 应用下载 | 没有安装或希望应用自行管理 | 展示目标位置，用户点击下载，显示下载、校验、准备和版本检测，成功后采用 |

每个工具只有一个来源下拉框，选中后才展开相应操作。检测新路径失败时保留上一份可用配置。PATH 用于寻找程序，版本还需要调用工具的版本参数检测，并非直接从环境变量取得。PATH 与手动配置的工具仍由原安装方式更新；应用只管理自己的下载副本。

下载默认放到应用执行目录的 tools 子目录，各工具独立存放。Windows 安装到只读目录时可能无法写入，所以原型加入“执行目录不可写 → 改存到应用数据目录”的流程。不是静默切换位置，用户能看到最终路径；后端调用最终路径而非修改全局 PATH。

原型“演示选项”覆盖 PATH 未找到、文件不匹配、目录不可写、下载失败、取消、成功和配置切换。所有版本和安装进度均为示例；手动选择按钮填入示例路径，不打开真实系统选择器。没有安装或执行下载工具。

### 必备工具范围与更新通道

下载核心为 yt-dlp；音视频合并和最终规格检测使用 FFmpeg 与 FFprobe，统一配置一组工具。YouTube 完整支持还需要兼容的 JavaScript 运行时与 EJS 组件：可复用 PATH 中兼容的 Node.js，应用下载方案则使用 Deno。正式实现必须检查实际 yt-dlp 安装方式与 EJS 是否匹配，不能只检查一个 deno.exe 就声称 YouTube 可用。

依据 [yt-dlp EJS 官方说明](https://github.com/yt-dlp/yt-dlp/wiki/EJS)：当前指南列出 Deno 2.3.0+、Node.js 22.0.0+，Deno 默认启用，Node.js 需显式启用；官方独立 yt-dlp 可执行文件包含 EJS，pip 或其他安装方式需另查组件。版本要求可能变化，应按采用的 yt-dlp 版本检测。

依据 [yt-dlp 更新说明](https://github.com/yt-dlp/yt-dlp#update)：Stable、Nightly、Master 表示不同发布节奏，Nightly 也被官方推荐给常规用户，并不等同于“Stable 对所有站点最可靠”。首版界面不提供通道选择；应用维护经过验证的工具版本，后续再讨论更新策略。

### VideoCaptioner 是否整合

建议首版暂不列为必备工具。当前主目标是单视频解析、下载、合并和保存；字幕处理不影响这条流程。

[VideoCaptioner 官方项目](https://github.com/WEIFENG2333/VideoCaptioner)提供转写、优化、翻译、合成等 CLI 能力，部分功能可免费使用，LLM 功能另有配置。因此，下面的开发成本判断是基于功能范围的推断，并非测得的工期：

| 范围 | 对开发的影响 |
| --- | --- |
| 打开用户已安装的 VideoCaptioner | 较小，但传递文件方式仍需验证，不增加字幕任务 |
| 下载后调用 CLI 转写并保存字幕 | 增加工具与依赖检测、转写进度、取消、错误恢复和字幕输出验收，扩大首版周期 |
| 完整整合优化、翻译、字幕编辑与合成 | 增加模型/服务配置、字幕交互及更多处理任务，建议独立后续阶段 |

以后若要扩展，先验证单一“本地视频 → 转写字幕”的 CLI 流程，再考虑完整整合。此轮没有安装、运行或整合 VideoCaptioner。

## v0.6 原型定稿

2026-10-03，用户确认其余设计无异议，完成以下两项调整后定稿：设置页移除模块切换栏，从上到下展示系统设置、必备工具、关于；Cookie 导入统一使用工具栏下方的展开面板，移除顶部布局选择与弹窗。

封面与时长、三个联动下载选项、整行进度条、固定在卡片内的下载按钮、完成后的查看记录入口，以及三种工具来源均保留。当前界面和交互原型已定稿；正式开发前仍需逐平台验证解析与下载、Cookie 保存、工具安装、容器兼容性、进程取消与历史持久化策略。

最终验收应以文件为依据：可播放、有声音、规格符合选择、保存位置明确；失败后应用仍可继续操作。
